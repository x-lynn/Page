# **个人任务管理应用设计文档**

## **I. 项目概览**

| 属性 | 描述 |
| :---- | :---- |
| **项目名称** | 个人任务管理 APP (UniTask) |
| **项目目标** | 构建一个简洁、高效、跨平台的个人任务管理工具。 |
| **主要平台** | H5 (部署至 GitHub Pages) / 微信小程序 |
| **用户群体** | 寻求轻量级任务管理解决方案的个人用户。 |
| **核心价值** | 快速记录、跨设备同步、数据安全、免费部署。 |

## **II. 技术选型**

| 角色 | 技术/服务 | 理由 |
| :---- | :---- | :---- |
| **前端框架** | **uni-app (基于 Vue 3\)** | 核心优势是“一次开发，多端部署”，完美支持 H5 和微信小程序，统一代码库。 |
| **前端状态管理** | **Pinia (推荐)** | Vue 3 推荐的状态管理库，轻量、类型友好、易于集成。 |
| **后端即服务 (BaaS)** | **Supabase** | 提供 PostgreSQL 数据库、用户认证 (Auth)、实时订阅 (Realtime) 和存储 (Storage) 等一站式服务。 |
| **CI/CD** | **GitHub Actions** | 实现代码提交后的自动构建、测试和部署流程，提高开发效率。 |
| **H5 部署** | **GitHub Pages** | 利用 GitHub Pages 免费且快速地部署 H5 版本应用。 |

## **III. 模块设计**

### **3.1. Supabase 数据库结构设计**

#### **3.1.1. 主表：tasks (任务列表)**

为了支持每日任务和标准任务的区分，新增 task\_type 字段。

| 字段名称 | 类型 | 描述 | 约束 |
| :---- | :---- | :---- | :---- |
| **id** | UUID | 任务唯一标识符 | Primary Key |
| **user\_id** | UUID | 关联用户 ID | Foreign Key (auth.users) |
| **title** | text | 任务标题 | Not Null |
| **description** | text | 详细描述 | Nullable |
| **due\_date** | timestampz | 截止日期/时间 (主要用于标准任务) | Nullable |
| **task\_type** | varchar | **任务类型：Standard/Daily** | Not Null (Default: Standard) |
| **priority** | varchar | 优先级：Low/Medium/High | Not Null (Default: Medium) |
| **status** | varchar | 状态：Todo/Doing/Done | Not Null (Default: Todo) |
| **created\_at** | timestampz | 任务创建时间 | Default: now() |
| **is\_archived** | boolean | 是否已归档 | Not Null (Default: false) |

#### **3.1.2. 用户元数据表：users**

用于存储匿名用户的个性化设置和元数据。

| 字段名称 | 类型 | 描述 | 约束 |
| :---- | :---- | :---- | :---- |
| **id** | UUID | **Supabase Auth User ID** | Primary Key, Foreign Key (auth.users) |
| **created\_at** | timestampz | 记录创建时间 | Default: now() |
| **last\_activity** | timestampz | 最后活跃时间，用于更新。 | Nullable |
| **nickname** | varchar | 用户昵称，在 Profile 页可编辑。 | Default: '匿名用户' |
| **showdoc\_push\_link** | text | Showdoc 或其他外部通知推送链接 | Nullable |

**注意：** Supabase URL 和 Anon Key 为系统级配置，通过环境变量设置，不存储在 users 表中。

**关键安全策略 (RLS):**

1. **tasks 表 RLS 策略：** 确保用户只能访问和修改 user\_id 等于其自身认证 ID (auth.uid()) 的任务。  
   * **USING/CHECK:** auth.uid() \= user\_id  
2. **users 表 RLS 策略：** 确保用户只能读取和更新自己的元数据记录。  
   * **USING/CHECK:** auth.uid() \= id

### **3.2. 核心功能设计 (更新重点)**

| 模块 | 功能点 | 描述 |
| :---- | :---- | :---- |
| **用户认证** | **设备持久化匿名身份** | **应用启动时静默调用 Supabase Auth 的匿名登录功能。通过本地存储，用户的匿名 ID (UUID) 将持久保存在该设备上，确保该设备用户身份的唯一性与任务数据的连续性。** |
| **任务创建** | 快速添加任务 | 简洁的输入界面，可选择创建**标准任务**或**每日任务**。 |
| **任务类型管理** | **每日任务视图** | **单独展示每日任务，并支持用户手动或系统自动（未来扩展）重置每日任务的完成状态。** |
| **任务列表** | 主视图/列表 | 展示标准任务的待办、进行中、已完成任务，支持下拉刷新。 |
| **任务详情** | 查阅/编辑 | 查看和修改任务的标题、描述、截止日期、状态、优先级和任务类型。 |
| **筛选与排序** | 筛选工具 | 支持按**截止日期**、**优先级**、**状态**和**任务类型**进行筛选和排序。 |
| **设置管理** | **应用配置** | **允许用户配置外部通知推送链接（如 Showdoc 推送）。此功能集成在 Profile 页面中，配置数据存储在 users 表的 showdoc\_push\_link 字段中。Supabase URL/Key 为系统级配置，通过环境变量设置，不在用户设置中管理。** |
| **归档功能** | 任务归档 | 将已完成或不活跃的标准任务移至归档列表。 |

## **IV. 架构设计**

### **4.1. 客户端架构 (uni-app)**

1. **目录结构:**  
   * /pages: 页面文件 (**Index/Home, DailyTasks, Detail, Profile**)。  
     * **Index/Home:** 标准任务列表页。  
     * **DailyTasks:** 每日任务列表页。  
     * **Detail:** 任务详情/编辑页。  
     * **Profile:** 个人中心页，**包含认证信息显示和应用配置（设置）功能**。  
   * /components: 可复用组件 (TaskCard, PriorityBadge, FilterModal, SettingsForm)。  
   * /stores: Pinia 状态管理模块 (e.g., tasksStore 负责任务数据和 Supabase 交互, settingsStore 负责用户个性化配置如 showdoc_push_link)。  
   * /utils: 工具函数和 Supabase 客户端初始化。  
2. **Supabase 集成:**  
   * 在 /utils/supabase.js 中初始化 Supabase 客户端。  
   * **登录流程:** **应用启动时自动静默调用 supabase.auth.signInAnonymously()。**  
   * **数据操作:** 所有 CRUD 操作封装在 tasksStore 中，通过调用 Supabase SDK 实现。  
   * **实时同步 (可选):** 在主任务列表页面，可以使用 Supabase Realtime 监听 tasks 表的变动，实现多设备间的任务实时同步。

### **4.2. 后端架构 (Supabase)**

1. **数据库 (PostgreSQL):** 存储任务数据和用户元数据。  
2. **用户认证 (Auth):** 统一管理用户身份，采用**匿名认证**作为主要的登录方式。  
3. **API 网关:** uni-app 客户端通过 Supabase RESTful API 与数据库交互。  
4. **安全核心 (RLS):** 严格执行 Row-Level Security，防止数据泄露和跨用户访问。

## **V. 部署与 CI/CD 方案**

### **5.1. H5 部署 (GitHub Pages \+ GitHub Actions)**

目标：代码合并到 main 分支后，自动构建 H5 代码并部署到 GitHub Pages。

| 步骤 | 描述 | GitHub Actions 关键操作 |
| :---- | :---- | :---- |
| **1\. 触发** | 监听 push 到 main 分支的事件。 | on: push: branches: \[main\] |
| **2\. 环境设置** | 设置 Node.js 环境。 | uses: actions/setup-node@v4 |
| **3\. 依赖安装** | 安装 uni-app 项目依赖。 | run: npm install |
| **4\. H5 构建** | 执行 uni-app 的 H5 平台构建命令。 | run: npm run build:h5 |
| **5\. 部署到 Pages** | 将构建产物 (/dist/build/h5) 部署到 gh-pages 分支。 | uses: peaceiris/actions-gh-pages@v3 / github-pages-deploy-action |

### **5.2. 微信小程序部署 (GitHub Actions \+ 微信开发者工具 CLI)**

## **VI. Supabase 集成和安全注意事项**

### **6.1. Supabase 初始化 (uni-app)**

// /utils/supabase.js  
import { createClient } from '@supabase/supabase-js';  
import { getEnvVar } from './settings'; // 获取环境变量的函数

// Supabase 配置为系统级设置，从环境变量获取  
const SUPABASE\_URL \= getEnvVar('VUE\_APP\_SUPABASE\_URL');  
const SUPABASE\_ANON\_KEY \= getEnvVar('VUE\_APP\_SUPABASE\_ANON\_KEY');

export const supabase \= createClient(SUPABASE\_URL, SUPABASE\_ANON\_KEY, {  
  // 针对 uni-app 环境的特殊配置  
  auth: {  
    // \*\*核心：通过本地存储机制实现设备身份持久化\*\*  
    persistSession: true, // 保持匿名会话的持久性，Supabase 会在本地存储一个 token  
    storage: {  
      // uni-app 适配器：将 Supabase 的存储操作映射到 uni.setStorageSync/uni.getStorageSync  
      getItem: (key) \=\> uni.getStorageSync(key),  
      setItem: (key, value) \=\> uni.setStorageSync(key, value),  
      removeItem: (key) \=\> uni.removeStorageSync(key),  
    }  
  }  
});

/\*\*  
 \* 自动静默登录：  
 \* 1\. 检查是否存在活跃会话（即本地存储中是否有有效的匿名 token）。  
 \* 2\. 如果不存在，则调用 signInAnonymously() 创建一个新的匿名用户，并将其 UUID 存储在设备本地。  
 \* 3\. 任何数据操作都必须等待此过程完成后才能进行。  
 \*/  
export async function ensureAuth() {  
  const { data: { session } } \= await supabase.auth.getSession();  
  if (\!session) {  
    // 如果没有会话，自动进行匿名登录  
    const { error } \= await supabase.auth.signInAnonymously();  
    if (error) {  
      console.error('自动匿名登录失败:', error.message);  
      // TODO: 在应用UI中显示一个不引人注目的错误提示  
    }  
  }  
}

// 首次进入应用或会话过期时，应用的核心初始化逻辑将在后台自动尝试 ensureAuth()  
// 确保在任何数据操作之前，都已获取到一个有效的匿名用户会话。
